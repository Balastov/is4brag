# КИСУ «Метро» — Поиск по проектной документации

Отвечай на вопросы пользователей по документации КИСУ «Метро», выгруженной из Confluence (`conf-metro.ibs.ru`).

## База знаний

Гибридный поиск (Qdrant dense + SQLite FTS5, с совместимым standalone
semantic + TF-IDF fallback) по **4 разделам**, объединённым через Reciprocal Rank Fusion:

| Раздел | Чанков | Описание |
|---|---|---|
| Стадии проекта | 8 484* | Проектные решения (ПР), опросные листы, обследования, BPMN-модели, концепции тестирования, traceability-матрицы, **спецификации требований** к подсистемам (УФ 01.01–01.03, УМИ, UMTO, UTR, UDO, UPO) |
| Архитектура | 3 375 | Целевая архитектура, описание контуров, справочники, интеграционные модели |
| Управление проектом | 7 054 | Протоколы советов (УС, ОС, Архитектурный комитет, рабочие группы), реестры |
| Термины и сокращения | 51 | Глоссарий: 44-ФЗ, 223-ФЗ, и др. |

**Всего: 18 964 чанка** из Confluence `conf-metro.ibs.ru`.

**Модель:** `intfloat/multilingual-e5-large` (1024-мерные эмбеддинги), TF-IDF (max_features=10000), RRF 60/40 (семантика/TF-IDF).

**Синхронизация:** ежедневно в 21:00 через Confluence PAT API (`--skip-index`: только чанки). Индексы — отдельным прогоном на хосте (инкремент по page_id; полный resumable «Стадий» — вручную / `--full-reindex`).

## Принцип работы

Поиск выполняется **одновременно по всем 5 разделам**, результат объединяется через Reciprocal Rank Fusion. Ранжирование:
- Семантический поиск (60% веса) — находит документы по смыслу, даже если слова не совпадают
- TF-IDF поиск (40% веса) — точный лексический поиск по ключевым словам

Ключ RRF = `(section, chunk_id)` — гарантирует отсутствие коллизий между разделами.

## Поисковый скрипт

Если задан `SEARCH_API_URL`, скрипт сначала вызывает долгоживущий search API:
модель прогрета и переиспользуется между запросами. При недоступности API он
по умолчанию завершает поиск ошибкой, чтобы не вернуть удалённые или устаревшие
данные. Прежние файловые индексы используются только при явном
`SEARCH_API_LEGACY_FALLBACK=1`. Без `SEARCH_API_URL` standalone-режим сохраняется.
`KISU_METRO_BASE` задаёт каталог standalone-индексов.
Аргументы CLI и JSON-контракт одинаковы для обоих режимов.

```bash
python3 "/app/skills/public/kisu-metro/scripts/kisu_metro_search.py" "ТЕКСТ ЗАПРОСА" --top-k 5 --json
```

### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `«запрос»` (1-й аргумент) | (обязательно) | Поисковый запрос на русском |
| `--top-k N` | 10 | Количество возвращаемых чанков |
| `--section S` | все разделы | Фильтр, имя раздела указывается точно: `«Стадии проекта»`, `«Архитектура»`, `«Управление проектом»`, `«Термины и сокращения»`. Неточное имя даёт пустой результат. Спецификации требований входят в `«Стадии проекта»` — отдельного раздела для них нет. |
| `--json` | — | Вывести результат в JSON |
| `--verbose` | — | Подробный вывод в stderr |

### Примеры

```bash
# Поиск по всем разделам
python3 "/app/skills/public/kisu-metro/scripts/kisu_metro_search.py" "матрица соответствия требований" --top-k 5 --json

# Поиск только в архитектуре
python3 "/app/skills/public/kisu-metro/scripts/kisu_metro_search.py" "описание контуров" --section "Архитектура" --top-k 3 --json

# Поиск по терминам
python3 "/app/skills/public/kisu-metro/scripts/kisu_metro_search.py" "44-ФЗ" --section "Термины и сокращения" --top-k 1 --json

# Поиск UDO
python3 "/app/skills/public/kisu-metro/scripts/kisu_metro_search.py" "UDO управление документированной информацией" --top-k 5 --json
```

## Формат ответа JSON

```json
[
  {
    "chunk_id": 17192,
    "section": "Стадии проекта",
    "title": "ПР_UDO_01.01.13 Управление документацией",
    "url": "https://conf-metro.ibs.ru/pages/viewpage.action?pageId=12365863",
    "page_id": "12365863",
    "text": "УДО 01 Управлять документированной информацией...",
    "score": 0.6
  }
]
```

Поле `section` указывает, из какого раздела пришёл результат.

## Алгоритм ответа

1. **Получи запрос** от пользователя
2. **Сформулируй поисковый запрос** — максимально точно отражающий суть вопроса
3. **Выполни поиск** через скрипт, разбери JSON
4. **Прочитай найденные чанки** и выбери наиболее релевантные фрагменты
5. **Сформулируй ответ**, опираясь на текст документации:
   - Приведи точную информацию из найденных фрагментов
   - Укажи источник: название страницы Confluence и ссылку (поле `url`)
   - Если информации недостаточно, попробуй переформулировать запрос или скажи пользователю
6. **При необходимости** уточни у пользователя, в каком разделе искать (особенно если запрос неочевиден)

## Ограничения

- Индексы статические — отражают чанки/эмбеддинги на момент последней индексации (чанки обновляются ежедневно в 21:00)
- Размер чанков настраивается; content-aware стратегия сохраняет headings, строки таблиц и metadata требований
- Canonical/API-результаты содержат `breadcrumbs`; legacy-файлы могут не иметь этого поля
- При первом запуске скрипт загружает модель и индексы (~8 сек для всех разделов)
- TF-IDF использует `TfidfVectorizer` (max_features=10000) — может не находить редкие термины в малых разделах (например, «Термины и сокращения»)
